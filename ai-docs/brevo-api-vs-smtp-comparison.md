# Brevo API vs SMTP 发送方式对比

## 当前使用方式：Transactional Email API

### 优势 ✅

1. **更好的状态跟踪**
   - 返回 `messageId`，可以精确查询每封邮件的状态
   - 在 Brevo 后台可以查看详细的发送日志和事件
   - 支持查询：已发送、已送达、已打开、已点击等状态

2. **更好的错误处理**
   - 明确的错误响应和状态码
   - 详细的错误信息，便于调试
   - 可以精确知道哪些邮件发送失败及原因

3. **更适合批量发送**
   - 无需维护 SMTP 连接
   - 可以并发发送多封邮件
   - 自动处理速率限制

4. **更灵活的个性化**
   - 支持模板参数
   - 支持动态内容替换
   - 支持附件、标签等高级功能

5. **更好的集成**
   - RESTful API，易于集成
   - 与 Next.js API Routes 完美配合
   - 可以使用 fetch 直接调用

### 劣势 ❌

- 需要 API Key（但您已经有了）
- 依赖网络请求（但对于服务器端不是问题）

## SMTP 方式

### 优势 ✅

1. **传统方式，兼容性好**
   - 大多数邮件库都支持 SMTP
   - 可以通过邮件客户端发送

2. **简单直接**
   - 对于简单的邮件发送，代码可能更简单

### 劣势 ❌

1. **状态跟踪困难**
   - 难以精确跟踪每封邮件的状态
   - 需要额外配置才能获取发送报告

2. **错误处理不够详细**
   - SMTP 错误信息通常不够详细
   - 难以知道邮件是否真正送达

3. **需要维护连接**
   - 需要管理 SMTP 连接池
   - 连接可能断开，需要重连机制

4. **批量发送效率较低**
   - 需要逐个发送
   - 难以并发处理

5. **速率限制处理复杂**
   - 需要自己实现速率限制
   - 容易触发限制导致发送失败

## 推荐方案

### ✅ 继续使用 Transactional Email API（推荐）

**原因：**
1. 您已经成功配置并运行
2. API 返回了 `messageId`，可以精确跟踪
3. 更适合批量发送和程序化处理
4. 错误处理和状态跟踪更完善
5. 与 Next.js 集成更好

### 📊 性能对比

| 特性 | Transactional API | SMTP |
|------|------------------|------|
| 状态跟踪 | ✅ 精确（messageId） | ❌ 困难 |
| 错误处理 | ✅ 详细 | ⚠️ 一般 |
| 批量发送 | ✅ 高效 | ⚠️ 较慢 |
| 集成难度 | ✅ 简单 | ⚠️ 中等 |
| 速率限制 | ✅ 自动处理 | ❌ 需自己处理 |
| 日志查看 | ✅ 后台详细 | ⚠️ 有限 |

## 如果仍想使用 SMTP

如果您有特殊需求需要使用 SMTP，可以使用 Node.js 的 `nodemailer` 库：

```javascript
const nodemailer = require('nodemailer');

const transporter = nodemailer.createTransport({
  host: 'smtp-relay.brevo.com',
  port: 587,
  secure: false,
  auth: {
    user: '9aa2e1001@smtp-brevo.com',
    pass: 'YOUR_SMTP_PASSWORD', // 不是 API Key，需要单独的 SMTP 密码
  },
});
```

**注意：** SMTP 需要单独的密码，不是 API Key。
